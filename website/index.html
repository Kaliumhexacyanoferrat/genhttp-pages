Your GitHub Pages site, hosted on GenHTTP Lambda.

GenHTTP Pages replaces actions/deploy-pages. Keep your workflow, your build and your artifact. Change the step that deploys, hand it a key, and the next push publishes to your-site.genhttp.run.

Why not just GitHub Pages?

GitHub Pages serves files. A lambda serves the same files, can run code beside them, and comes with an editor that shows what happens on your site. Where GitHub is ahead, the table says so too.

Every site gets an editor

The editor key you store in the repository also opens the lambda's editor on genhttp.dev. This is the one of this page:

Know your traffic, without a tracking script

Requests per minute and per day, what failed or was not found, how fast the site answered and which pages are read. The server counts them, so there is no script on your pages, no cookie, and nothing for a consent banner.

See every request

A live log of what your site answered, with status, size and time, and once there is code beside the site, what it printed and the errors it threw. The 404s of a broken link show up here before anyone writes to you. Visitor addresses are not recorded.

Every push is a version

Each deployment is kept with the commit it came from. Compare any two, or put an older one back online while you fix the build that broke the site.

A server, when the site needs one

A contact form, a counter, an API whose key must not reach the browser, comments kept in a database, a page that updates itself: name a folder of C# in backend and it runs beside the site, on the same address. Records are in a SQLite database you can read in the editor, keys in secrets. The demos show a game over websockets and a live poll.

    Its editor key. Copy it now: it is shown only once, and it is the only way to change the lambda.

    The key opens the lambda's editor, where you see every deployment, roll one back, read the traffic and change the address. Treat it like a password.

  2. Store the key in your repository

    Add a repository secret named GENHTTP_KEY with the editor key as its value. Secrets are never shown in logs, and GitHub Pages is not involved, so the repository does not need Pages enabled.

Reference

Kaliumhexacyanoferrat/genhttp-pages@v1 takes every input of actions/deploy-pages, so a workflow keeps working as it is, and answers with the same page_url.

The inputs of deploy-pages

InputDefaultWhat it does here
artifact_namegithub-pagesThe artifact to publish, as actions/upload-pages-artifact made it in an earlier job of the run.
timeout600000Milliseconds to wait for the upload.
previewfalsePublishes to a feature of the lambda instead, with an address of its own, named after the pull request. Delete it in the editor when you are done.

error_count, reporting_intervalAccepted and not used: a lambda answers at once, so there is nothing to poll.

Its own inputs

InputDefaultWhat it does
keyThe editor key of the lambda, from a secret. Left out, the GENHTTP_KEY environment variable is read.
pathPublish this folder rather than an artifact.
branchPublish this branch, as GitHub's “Deploy from a branch” does.
folder/With branch: the folder to publish, / or /docs.

Configuring the build

actions/configure-pages keeps working while GitHub Pages is enabled for the repository. To switch Pages off, use its drop-in, which answers with the lambda's address instead, without a base path: 

- id: pages
  uses: Kaliumhexacyanoferrat/genhttp-pages/configure@v1
  with:
    key: ${{ secrets.GENHTTP_KEY }}
# ${{ steps.pages.outputs.base_url }} is https://my-site.genhttp.run

It does not rewrite the configuration of a static site generator as configure-pages does with static_site_generator; a site at the root of its address needs no base path.

How the site is served

The way GitHub Pages serves it:

  • /docs/ answers with docs/index.html, and /docs sends you there.
  • /about answers with about.html.
  • What is not there answers with your 404.html and status 404.
  • Every answer may be cached for ten minutes, is readable from any origin, and an unchanged file answers 304.
  • Names with spaces, accents, no extension or many folders work as they do on GitHub.

A backend beside the site

A static site sometimes needs one endpoint: a form, a counter, a proxy to an API with a key. Put C# into a folder and name it in backend. Its lambda.cs puts routes in front of the site, and the site still answers everything else: 

// backend/lambda.cs
var api = Inline.Create()
                .Get("hello", (string name) => $"Hello, {name}!");

return Layout.Create()
             .Add("api", api)
             .Add(PagesSite.Create());

This page does it: its backend creates the lambda in the first step. Secrets and a database are switched on in the lambda's editor; read about them in the GenHTTP Lambda guide.

What is different from GitHub Pages

The address
Your site answers at https://name.genhttp.run/. A project site built for owner.github.io/repository/ still works: it is served at the root and below /repository/.
How long it stays online
A free lambda stays online as long as it is used. One that nobody visits and nobody deploys to for a month goes offline, and is removed two months after that. The premium tier keeps it online.
Size
A free lambda holds 32 MB per deployment, against GitHub's 1 GB. The action says so before it uploads, and how large the site is.
Your own domain
Comes with the premium tier, set in the lambda's editor. A CNAME file is published like any other file.
Permissions
None needed: pages: write, id-token: write and the github-pages environment do no harm and can stay.
History
Every deployment is a version you can read, compare and put back online in the lambda's editor.
